# Release gates: Flow Tower v0.8.0

Release candidate: `chore/release-v0.8.0` at the top of a merge chain, checked on 2026-10-12. The chain runs #150 → #151 → #152 → #153 → #154 → this PR, plus #146 already on main. What it holds:
- **Voice:** scroll the file, the Hub panel, node-type and library filters, and comparing nodes (#146: #145).
- **The CLI split** (#150: #126).
- **Command-center and satellite skills** (#151: #148).
- **The model benchmark:** live tower events and the first full run (#152: #105).
- **`--warm`, `--batch` and `cache_control`** for Claude models (#153: #149).
- **The dev squad's models**, chosen by the benchmark (#154: #105).

This is a gate run, not a full audit: the finders and the adversarial verifier of [v0.1.0](v0.1.0.md) did not run again.

**The squad that built it changed during the release.** The first PRs were coded by DeepSeek 4.1 Flash and reviewed by GLM 5.3 FlashX; from #126 on, the coder was **Claude Haiku 5.5**. The switch came from the benchmark and from a field trial in which four coders did the same real task. Results:
- **Coder trial:** Haiku took 11 steps for $0.016; DeepSeek took 36 steps for $0.048.
- **Reviewer comparison:** on the same PR, GLM took 3 steps for $0.007 and found the issue. DeepSeek also found it, but took 16 steps for $0.058. Gemini Flash Lite missed it.

**Checked by hand on a real server.** The test server's hub ran the release candidate, with a laptop satellite over an SSH tunnel. 50 of 50 events arrived, carrying metadata fields only (`call, host, id, kind, project, runtime, sender, session, source, targets, tool, ts, user`). A marker string in `message` never reached the hub. The top bar showed `HUB 1/1`, and `/api/version` reported 0.8.0.

**Skills tested by a fresh agent.** It followed `flow-tower-command-center` and `flow-tower-satellite` literally on loopback: a hub, a satellite, and a starter copied out. Results:
- All 5 success points passed.
- All 19 links resolved.
- The 10 unclear points it reported were fixed before merge.
