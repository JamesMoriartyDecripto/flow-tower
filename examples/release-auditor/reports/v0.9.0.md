# Release gates: Flow Tower v0.9.0

Release candidate: `chore/release-v0.9.0`, on top of `main` after the 2026-10-12 merge chain, checked on 2026-10-13. The chain: #168 → #170 → #172, #171 → #178, #175 → #180, #179, each brought up to date with `main` and green in CI before its merge. What it holds:
- **Hub:** one-step `connect` on a tailnet and tower `share` / `unshare` with auto-sync (#164), library sources and the FROM filter (#165), command-center kit findings from the real deployment (#166).
- **Documents:** the tower documentation as PDF, `flow-tower export --pdf` (#65), and the report studio, `flow-tower report` with five types (#174).
- **The tower optimizer:** `flow-tower audit`, `docs/best-practices.md` and the `flow-tower-optimize` skill (#173).
- **The squad:** pace (#169), bash `steps.sh` and the `Files:` check (#176).

This is a gate run, not a full audit: the finders and the adversarial verifier of [v0.1.0](v0.1.0.md) did not run again.

**Where it ran.** The Linux test server (no GPU, software WebGL). Its port 5317 is the live hub, so the e2e suite ran on port 5419 with a scratch Playwright config and the local Chromium, not as a plain `npm run e2e`; [e2e.log](e2e.log) is therefore still the v0.8.0 run. The full suite with a GPU is [#181](https://github.com/JamesMoriartyDecripto/flow-tower/issues/181), from the laptop.

| Step | Result |

**The 7 that still fail** are `towers.spec` cases on the largest example towers (AI Video Studio, Dev Squad, Forge Studio, Legal Due Diligence, Mobile App Studio, Syllabus Forge, Website & Web Design Studio): they time out drawing 3D in software WebGL. The same spec failed on 12 towers on `main` before this release, on the same server. The other 11 (the PDF at each level, remote activity, a voice phrase, smaller towers) failed only under two parallel workers and pass alone.

**Checked by hand on the server:**
- **PDFs:** all five report types printed. Each passed its 9 blocking checks. The pages were reviewed as PNG in two rounds, which found and fixed about ten layout defects that the checks had missed.
- **Tower documentation:** the tower documentation type produced the #65 PDF with its 3D snapshot.
- **Tower optimizer:** a fresh agent followed `flow-tower-optimize` literally on a tower outside the repository through all six phases (3 findings fixed, none new). It reported 12 unclear points, all fixed before merge.
- **Self-audit:** the optimizer audits its own example and the report studio with 0 findings.

**Not checked here:** a real tailnet test of #164 and #165 (two computers and the hub), PDFs with GPU-rendered 3D, and the plain `npm run e2e`. All three are in #181.
