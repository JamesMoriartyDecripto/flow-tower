# Release gates: Flow Tower v0.11.0

Release candidate: `chore/release-v0.11.0`, on top of `main` at `667fab1` (#225) plus two commits made on the branch (the example towers matched to the code, and the panel corners), checked on 2026-10-15. Merged since v0.10.0: #207, #214, #215, #216, #217, #218 (the #181 laptop checks), #219, #220, #221, #222, #223, #224, #225. What it holds:
- **The laptop checks of #181 (Fedora, Intel Iris Xe):** the document's 3D figures draw in Google Chrome again (#207); export, report and e2e use the GPU when there is one (#214, closes #209: dev-squad export 72 s → 16 s); four `service` defects found on a real `systemctl --user` (#215, #194 Linux side); a flaky axe test (#216).
- **The low findings of the second dry run (#211, closed):** library card titles wrap (#219); sub-cent budgets, the test alert's rule name, share names from the tower's `name:`, the loopback hint only without a configured `url`, `connect` and wired hooks, `guide`'s placeholder, Node 22's SQLite warning, one Machines row per sender, `simulate` says where it sends, and eco quality without a GPU (post-processing drew a dark rectangle under SwiftShader) (#221).
- **From the maintainer's use:** a remote hub view hides the MIC and says why (#222: voice stays refused to remote viewers, the maintainer's choice); the HUD tooltip measures itself and stays inside the window (#223); a description-length guideline with a `validate` warning, the example towers shortened to fit (#225).
- **Tests:** explicit timeouts for CLI-spawning tests that timed out under load (#220).
- **On the release branch:** the panels that scrolled their own box (node list, layer list, legend, validation, shortcuts) now scroll an inner element, so their corner marks stay on the frame (reported by the maintainer); a docs-vs-code check of the towers that map Flow Tower itself (team-hub, voice-commands, command-center, the e2e-sweep sub-tower, examples/README.md) against this release, and `SuccessExitStatus=130 143` in the command-center kit's systemd unit (without it a `systemctl stop` left the hub `failed`).

This is a gate run, not a full audit: the finders and the adversarial verifier of [v0.1.0](v0.1.0.md) did not run again.

**Where it ran.** The Fedora laptop (Intel Iris Xe, 7.4 GB RAM), for the first time a release with the GPU: the plain `npm run e2e` with `FLOW_TOWER_E2E_GPU=1` and one worker (two workers ran out of memory on 2026-10-15), so [e2e.log](e2e.log) is this run (94 tests, 0 not passed). The gates ran with a scratch user folder, so their live events reached no server.

**Checked by hand on the laptop and the live command center:**
- The 3D view in software WebGL (SwiftShader) vs the GPU: the dark rectangle reproduced only in software with post-processing; without a GPU the app now starts in eco and does not save it as a preference.
- The tooltip on every row of every layer (voice-commands, dev-squad) at 1440×800 and 1440×600: inside the window.
- A remote hub viewer (a `--hub` server, the tailnet header simulated): no MIC, V explains; the live command center after the pull and restart: page, read-only `me`, voice refused (403), the new modules served.
- The node list scrolled 124 px in a 1440×400 window: the corner marks stay on the frame.
- `guide`, `simulate` (target printed, a clear message when nothing answers), `validate` on a scratch tower with long descriptions.

**Not checked here:** a real tailnet with two computers and the macOS side of #194 (launchd) need the Mac; Caddy with a real certificate; real ntfy / Slack / Telegram endpoints. They stay in [#181](https://github.com/JamesMoriartyDecripto/flow-tower/issues/181). [#208](https://github.com/JamesMoriartyDecripto/flow-tower/issues/208) (troika fetches glyphs from jsdelivr, so label specs fail offline) is on hold by the maintainer.
