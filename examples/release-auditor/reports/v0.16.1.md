# Release gates: Flow Tower v0.16.1

Release candidate: `release/v0.16.1`, on top of `main` at `9dd26c3` (#392), checked on 2026-11-02. Merged since v0.16.0: #384, #385, #387, #388, #389, #390, #392.

A patch release: fixes to the squad runner and the CLI, and one security fix in the runner's plan gate.

- **Security: a comma in a plan file entry could hide a control path from the sign-off** (#391, PR #392). `src/a.js, .github/x` passed the control-file check as one path, then the task's `Files:` line split it in two and granted `.github/x` to the coder. A plan file entry with a comma or a line break is now refused.
- **Squad runner reads role answers where they are** (#369, PR #390).
  - The verifier's PASS was never read: `role()` returned the raw `run.mjs` output, whose first line is always `mode: …`. `reportOf` strips that header and the footer.
  - Triage, plan and judgement take the first json object block that validates, so an echoed template or a quoted draft no longer wins.
  - An unreadable triage answer is asked for once more; `file:~200` citations resolve.
  - A person can release one issue's plan sign-off with `SQUAD_APPROVE=<issue number>`, posted on the issue. A bare flag was refused in review: the runner polls many issues in one process.
- **CLI from a checkout path with spaces** (#307, PR #389): `report` and `export` start there, the update command quotes the folder, and the tests pass there.
- **Squad tooling:** commands with shell syntax refused at load (#382, PR #384); trimmed review packs flagged by the gate (#383, PR #385); the coder changes only the lines a task needs (#386, PR #387).
- **Docs:** the dev-squad example counts nine layers and no longer names GLM as the architect's model (#371, PR #388).

This is a gate run, not a full audit: the finders and the adversarial verifier of [v0.1.0](v0.1.0.md) did not run again.
