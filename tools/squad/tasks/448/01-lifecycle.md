Why: issue #448. An agent needs one script that starts the real app in isolation, says whether that instance is safe to drive, and stops it. A scratch server without its own FLOW_TOWER_HOME reads the user's config and joins the hub; port 5317 may be someone's live server.

Data: a run is a folder `<base>/<runId>/` holding `run.json` (`{ runId, port, pid, url, home, evidence, commit, startedAt }`), `home/` (the server's FLOW_TOWER_HOME), `evidence/` and `server.log`. `<base>` is `join(tmpdir(), 'flow-tower-verify')`, or `--base <dir>`. `<base>/current` is a text file with the path of the last launched run. Every command but `launch` takes `--run <dir>`, default the path in `current`.

1. New file .claude/skills/verify-flow-tower/scripts/verify.mjs (plain Node, no dependency for this step), run as `node .claude/skills/verify-flow-tower/scripts/verify.mjs <command>`:
   - Before any command: Node older than 22.13 prints `Node 22.13 or newer is needed (this is <version>)` and exits 2. The repo root is the git root of this file.
   - `--help` or no command: prints the commands with one line each, exit 0.
   - `launch [--port 5327] [--base <dir>]`: if something already answers on `http://127.0.0.1:<port>/api/workspace` or the TCP port accepts a connection, print `port <port> is in use: pick another with --port` and exit 1 without starting anything. Else create the run folder, spawn `process.execPath bin/flow-tower.js examples --no-open --port <port>` from the repo root, detached, stdout and stderr appended to `server.log`, env = the current env plus `FLOW_TOWER_HOME=<run>/home`, `FLOW_TOWER_NO_UPDATE_CHECK=1`. Write `run.json` and `current`. Poll `/api/workspace` every 500 ms for up to 90 s until it answers 200 with a JSON body whose `projects` array is not empty. On success print `ready <url>`, `run <dir>`, `projects <count>` and exit 0, leaving the server running. On timeout or if the child exits first: kill that PID, print the last 20 lines of `server.log`, exit 1.
   - `doctor [--run <dir>]`: read-only. Print one line per check, `ok   <name>: <detail>` or `FAIL <name>: <detail>`, exit 1 if any FAIL: `run.json` readable; the PID is alive (`process.kill(pid, 0)`); `/api/workspace` answers 200 with projects, and print the count and the first 5 project ids; the commit in run.json equals `git rev-parse HEAD` (a difference is `FAIL commit: launched at <a>, checkout is at <b>`).
   - `stop [--run <dir>]`: send SIGTERM to the recorded PID's process group (the server was spawned detached, so `process.kill(-pid, 'SIGTERM')`, falling back to the PID), wait up to 5 s for `/api/workspace` to stop answering, then SIGKILL. Remove `<run>/home` only. Print `stopped pid <pid>` and `evidence kept in <run>/evidence`. A PID that is already gone is not an error.
   - Export the pure helpers `planRun({ base, port, now })` (returns the run.json fields except pid and commit, with `runId` built from the time and the port) and `parseArgs(argv)`. Run the CLI only when the file is the entry script.
