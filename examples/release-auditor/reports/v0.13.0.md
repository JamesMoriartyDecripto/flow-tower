# Release gates: Flow Tower v0.13.0

Release candidate: `release/v0.13.0`, on top of `main` at `a77d2e9` (#294), checked on 2026-10-23. Merged since v0.12.0: #280, #282-#285, #288, #290, #292-#294. What it holds:
- **Hub security** (#286, PR #285; #287, PR #294). A listed viewer can open the files a shared tower references, and only those. A remote viewer loads only the app's own assets, where before it could read any file of the flow-tower checkout through Vite. `flow-tower.local.json` is in `fs.deny`.
- **Voice: a guided tour of the tower** (#275, PR #280).
- **Role catalogue re-checked** on the models new since 2026-10-16 (#281, PR #282).
- **Fixes:** library card titles on a hub (#279, PR #283); the "not sent by the satellite" message for a shared tower's missing file (#289, PR #290).
- **Docs and skills:** onboarding a teammate by sharing only the hub machine (PR #288). Towers before code, the audit step and the dev squad in the skills (#291, PR #292).
- **On the release branch:** the first full e2e run failed 1 of 103 tests, `every referenced file is served by /api/file`. The `model-benchmark` tower (#281) listed `../../skills/flow-tower-costs/catalogue.md` as a node file. That is outside `examples/`, so a server opened on the examples answers 403. `validate` did not flag it. The node now links the catalogue on GitHub, like its reference.md. The test passes, and the full suite ran again.
- **On the release branch, also:** `npm audit` failed on the second gate run, which happened after a new advisory came out: [GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5) (high: zod could exhaust memory while validating an oversized constrained collection). zod is now 4.6.7, a patch release in the same `^4` range. The gates and the full e2e ran again after the bump.

This is a gate run, not a full audit: the finders and the adversarial verifier of [v0.1.0](v0.1.0.md) did not run again.

**Where it ran.** The Fedora laptop (Intel Iris Xe, 7.4 GB RAM): the plain `npm run e2e` with `FLOW_TOWER_E2E_GPU=1` and one worker, so [e2e.log](e2e.log) is this run. The gates ran with a scratch user folder, so their live events reached no server.
