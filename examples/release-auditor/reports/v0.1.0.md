## Rejected

| Candidate | Why |
|---|---|
| `GET /api/events` ignores `FLOW_TOWER_TOKEN` | Rule 1: loopback only, cross-origin reads blocked (no CORS header, DNS rebinding refused by Vite), and the page itself reads it without a token; the token is documented as a write guard |
| semgrep `react-insecure-request` in `e2e/fixtures.ts` | Rule 1: loopback dev server |
| `THREE.Clock` deprecation warning | Rule 4: raised inside react-three-fiber |
| Layout overlaps at 1440, 1920, 1024 | Measured mid slide-in animation; clean once animations finish (suite now waits for them) |

## Deferred, then fixed before the tag

The maintainer chose to fix the minor leftovers instead of opening issues:

| Leftover | Fix |
|---|---|
| Legend edge styles and layer descriptions readable only with the mouse | Tooltips also open on keyboard focus; legend entries are focusable |
| Live feed rendered its list while closed; live hooks woke up 4 times a second while idle; tooltip watchdog always running | The feed mounts only when open; polling and the watchdog stop when nothing is live or shown |
| Any watched file change re-laid out the tower on screen (ELK) even if it did not change | Unchanged towers keep their object across reloads (`tests/regressions.test.ts`) |
| Italian customer templates in an English-only repo | Kept, declared in the sales-pipeline README and in CLAUDE.md |

Not changed, by design: the default `balanced` quality renders continuously while the window has focus;
`eco` idles at 0 renders.

The update notice idea raised during the sweep is tracked in #35.

## Lessons for the next sweep

- Finders with one charter each found different bugs with little overlap; the docs finder alone fixed 9 files.
- Half the first E2E failures were the suite, not the app (timing under load, mid-animation measurements, auto map view). Retry by time and wait for animations.
- The adversarial verifier rejected exactly the candidate the threat model said to reject.
