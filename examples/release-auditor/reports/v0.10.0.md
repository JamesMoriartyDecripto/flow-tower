# Release gates: Flow Tower v0.10.0

Release candidate: `chore/release-v0.10.0`, on top of `main` after the 2026-10-13 merge chain, checked on 2026-10-13. The chain: #185 → #186, then the team-UX plan #195 → #197 → #198 → #199 → #200 → #201 → #202 → #203 → #204 → #205 → #210, each brought up to date with `main` and green in CI before its merge. What it holds:
- **Hub admin and alerts:** Hub › Admin (#93), the alert rules (#94), the alert webhook and the `errors` rule (#191).
- **Team UX, from a newcomer dry run:** history counts hook errors (#187), the relay recovers by itself (#188), `hooks install` for every harness (#189), validated shared towers (#190), the harness parity test and the Pi fixes (#196, #5), Hub › Now (#192), CLI hints and the Caddy route without Tailscale (#193), `service install` (#194), the example towers and a docs-vs-code cross-check (#205).
- **Second dry run fixes (#206):** Admin PAUSE/RESUME, sender scoping on the hub, one main-agent name, Now session states, `service install` port check, the kit order.

This is a gate run, not a full audit: the finders and the adversarial verifier of [v0.1.0](v0.1.0.md) did not run again.

**Where it ran.** The Linux test server (no GPU, software WebGL). Its port 5317 is the live hub, so the e2e suite ran on port 5419 with a scratch Playwright config and the local Chromium, not as a plain `npm run e2e`; [e2e.log](e2e.log) is therefore still the v0.8.0 run. The gates ran with a scratch user folder, so their live events reached no server.

**The 16 that still fail** are `towers.spec` cases that time out drawing 3D in software WebGL while they walk every layer: AI Video Studio, Ambient Chief of Staff, Dev Squad, Ebook Studio, Forge Studio, Invoicing with Fatture in Cloud, Legal Due Diligence, Marketing Studio, Mobile App Studio, Release Auditor, Sales Pipeline, Social Media Studio, SRE Incident Responder, Syllabus Forge, Voice Commands, Website & Web Design Studio. **Not a regression:** Release Auditor and Voice Commands fail the same way on the `v0.9.0` tag, on the same server the same day; the server was busier than at v0.9.0 (load average 6-8), which then had 7 such failures.

**Two e2e tests were wrong, fixed in this release:**
- `every referenced file is served by /api/file` asked for `optional: true` files (#137) that a run writes later; it now skips the ones not generated yet (`missingOptional`).
- `voice: the new fixed phrases … open the hub` fakes a hub page on a library server, and the alert pill added by #94 polls `/api/hub/alerts`, which 404s there; the test now answers that route as `hub.spec` does.

**Checked by hand on the server:**
- **Two newcomer dry runs** (an agent following only the docs, as a lead and as teammates): the first found the team journeys rough (11 hand edits to wire hooks, restarts, silent alerts) and became #187-#196; the second found no broken journey and became #206 (fixed) and #211 (low findings, open).
- **Team hub with satellites:** two scratch satellites and a scratch hub on loopback: connect, share, pause from Hub › Admin, revoke and reconnect without a restart, a broken save kept off the hub, two teammates whose towers share a rule each lighting only their own tower.
- **Harnesses:** Pi 0.73.1 driven for real (extension and `--mode json`); Claude Code, Codex, Hermes and the Agent SDK through the parity fixtures.
- **Alerts:** the webhook delivered open and clear to a local receiver; the `errors` rule fired on 3 errors in 15 minutes.

**Not checked here:** a real tailnet with two computers, macOS launchd and a real `systemctl --user` unit for `service install`, Caddy with a real certificate in front of a hub, ntfy / Slack / Telegram endpoints (only a local receiver), the 3D view and PDFs with a GPU, and the plain `npm run e2e`. All are in [#181](https://github.com/JamesMoriartyDecripto/flow-tower/issues/181), from the laptop.
